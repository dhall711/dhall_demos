COMMON SQL DIFFERENCES:
-----------------------

1. STRING FUNCTIONS:
   SQL Server              Snowflake
   -----------             ---------
   LEN(x)                  LENGTH(x)
   STUFF(x,a,b,c)          INSERT(x,a,b,c)
   CHARINDEX(x,y)          POSITION(x IN y)
   +  (concatenation)      CONCAT() or ||

2. DATE FUNCTIONS:
   SQL Server              Snowflake
   -----------             ---------
   GETDATE()               CURRENT_TIMESTAMP()
   DATEADD(d,n,x)          DATEADD(day,n,x)
   DATEDIFF(d,x,y)         DATEDIFF(day,x,y)
   YEAR(x)                 YEAR(x) [same]

3. NULL HANDLING:
   SQL Server              Snowflake
   -----------             ---------
   ISNULL(x,y)             COALESCE(x,y) or NVL(x,y)
   NULLIF(x,y)             NULLIF(x,y) [same]

4. WINDOW FUNCTIONS:
   - Mostly compatible
   - Snowflake has better performance for large datasets

5. WITH (NOLOCK):
   - Remove all NOLOCK hints
   - Snowflake uses MVCC (no locking needed)

6. TEMP TABLES:
   SQL Server: #temp
   Snowflake: CREATE TEMPORARY TABLE or CREATE TRANSIENT TABLE

7. TOP vs LIMIT:
   SQL Server: SELECT TOP 100 *
   Snowflake: SELECT * LIMIT 100

SECTION 8: RISK MITIGATION
====================================================================

HIGH-RISK ITEMS:
----------------

1. DATA VOLUME (638 GB):
   Risk: Long migration time, network issues
   Mitigation:
   - Use Snowflake's bulk loading (COPY INTO)
   - Compress files before transfer
   - Migrate in batches (by date range)
   - Parallel loading for large tables

2. COMPLEX VIEWS (215 views):
   Risk: SQL incompatibilities, logic errors
   Mitigation:
   - Automated SQL conversion tool
   - Thorough testing of each view
   - Row count validation
   - Sample data comparison

3. MDX TO SQL CONVERSION:
   Risk: Complex time-series calculations
   Mitigation:
   - Document all MDX logic
   - Convert to SQL window functions
   - Use dbt for complex metrics
   - Extensive testing

4. PERFORMANCE:
   Risk: Queries slower than SSAS cube
   Mitigation:
   - Implement clustering keys
   - Use materialized views for aggregations
   - Enable search optimization
   - Query result caching
   - Optimize warehouse sizing

5. USER ADOPTION:
   Risk: Users prefer old cube/tools
   Mitigation:
   - Training programs
   - Parallel run period
   - Modern BI tools (Power BI, Tableau, Looker)
   - Self-service analytics

6. MISSING OBJECTS:
   Risk: 39 tables have no data
   Mitigation:
   - Verify if truly needed by cube
   - Check if deprecated/staging
   - Document assumptions
