Key Component: DrilldownPanel

Reusable AI investigation component used across Dashboard, Partners, Devices, Chains, Lifecycle, and Forecast pages.

Behavior:
1. Mounts → checks seed cache for instant response
2. If cached → renders immediately (green ⚡ badge)
3. If not cached → POSTs to /api/chat with streaming
4. Background-prefetches drill-down responses
5. Drill-down pills → instant if prefetched, else live API 

interface DrilldownProps {
  pageId: string;
  question: string;
  title: string;
  onClose: () => void;
  drilldowns?: {
    label: string;
    question: string;
  }[];
  cacheKey?: string;
}

🔒 Authentication

SPCS OAuth (Zero-Config)

The application runs inside SPCS and uses the platform-mounted OAuth token — no secrets management required.

// Token auto-mounted by SPCS runtime
const token = fs.readFileSync('/snowflake/session/token', 'utf-8').trim();

// Host injected as env var by SPCS
const host = process.env.SNOWFLAKE_HOST;

// All API calls use OAuth bearer
headers: {
  'Authorization': `Bearer ${token}`,
  'X-Snowflake-Authorization-Token-Type': 'OAUTH'
}

🚀 Deployment

Build & Deploy Pipeline
# 1. Build for linux/amd64 (SPCS requirement)
docker build --platform linux/amd64 -t sfsenorthamerica-dhall-aws1.registry.snowflakecomputing.com\
  /comcast_cyber_demo/cert_security/app_repo/cert-chat:v12 .

# 2. Login to Snowflake container registry
snow spcs image-registry login

# 3. Push image
docker push sfsenorthamerica-dhall-aws1.registry.snowflakecomputing.com\
  /comcast_cyber_demo/cert_security/app_repo/cert-chat:v12

# 4. Deploy service (SQL)
ALTER SERVICE COMCAST_CYBER_DEMO.CERT_SECURITY.CERT_CHAT_SERVICE
  FROM SPECIFICATION $$ ... $$;

Critical: ENV HOSTNAME=0.0.0.0 in Dockerfile — Next.js standalone binds to localhost by default, unreachable inside SPCS.

💡 Design Decisions

DecisionRationale
Next.js standalone (not Streamlit)Full control over UI, multi-page SPA, supports SPCS deployment with custom routing
Inline SVG map (not Leaflet)SPCS CSP blocks external tile servers and CDN scripts
Interactive Table + IWH for dashboardSub-second KPIs on pre-aggregated 50M rows without full table scan
3 Semantic Views (not 1)Intelligent routing: fast IWH aggregates, full detail via standard WH, policy separate
pg_lake Shared IcebergZero-infra CDC from Postgres (~30s lag, no Openflow, no S3 bucket needed)
Seed cache + prefetchInstant first-click responses in demo, background-prefetch drill-downs
ChatContext providerPersists all AI interactions across page navigation (no state loss)
Light mode themeBetter visibility for remote demo presentations
